# 修复记录 2026-10-05（v1.5.58 维护轮）

本轮为只读体检后的问题修复，全部改动已通过语法编译、导入冒烟与端到端 API 验证，引擎已重启并健康运行。回滚备份：`backups/before-manual-fix-20261005/`（49 个文件）。

## 修复清单（按模块）

### capture.py / winstruct.py
- PrintWindow 兜底 GDI 句柄泄漏：位图未复位就 DeleteObject（每次 _grab 泄漏一张位图）→ 先 SelectObject 复位旧对象再删；CreateCompatibleBitmap 失败时 hdc 也释放。
- 定位态高 CPU：WGC 每帧全量重跑 chat_area → 画面逐像素未变直接跳过 + 0.5s 节流；chat_area 用 int16 替代 int64 全帧临时数组；极窄窗口采样为空时返回 None。
- _Settler 状态迁移加锁（WGC 回调线程与主循环并发），settled 原子取走 pending。
- on_frame_arrived 异常不再逃逸进原生回调（丢帧/状态半路）。
- PrintCapture 兜底模式画面长时间不变时降频到 1s。
- OpenProcess/QueryFullProcessImageNameW/CloseHandle 补 restype/argtypes（64 位句柄截断）。

### engine.py / deepseek.py
- 视觉后预算留 3 次不够（判断+起草+核验+排序需 4 次）→ 留 4 次；judge/rank 阶段捕获 TimeoutError 降级；draft/review 的 TimeoutError 转为可读错误而不是整次分析白算。
- deepseek 200 响应体解析全部归一化为 LlmError（非 JSON/结构异常不再裸抛）。
- analyze 超时从硬编码 40 改为跟随 generation_timeout（总预算仍由 route deadline 硬约束）。

### memory.py / replycache.py
- 记忆丢失根因：load_memory 只认 source=='user_confirmed'，但保存从不写该字段 → merge_memory 保留 source；extract 遇到已确认档案直接返回（模型提取永不覆盖用户确认）。
- merge_memory 校验 facts/open_items 必须是字符串列表（防逐字符写垃圾条目）。
- 记忆读写失败不再静默：写入引擎日志。
- replycache 缓存/飞行合并键只取内容相关字段，剥除 observed_at/sequence/evidence 等易变元数据（同证据重复观察时 20s 缓存真正命中，省一次模型调用）。

### junshi.py
- 独立模式（不经 launcher 直接跑引擎）自动开浏览器是死代码 → 用环境变量判断 standalone，面板 URL 带 #token。
- 退出时删除自己写的端口文件（含校验内容匹配的共享文件），不再残留死端口。
- flash_dsh_window 枚举时跳过本进程窗口（跨线程 GetWindowTextW 死锁）。
- 鉴权拒绝日志限速（10s 一条），_json 写回吞掉客户端断开异常（不再刷 traceback）。
- 配置写入用唯一临时名（并发 /settings 不会交错写坏配置）。
- 主循环兜底日志保留最后 3 行 traceback。
- analysisdiag 失败不再掩盖原始错误。
- readers 按会话 LRU 上限 8（联系人多了内存不再无限增长）。
- /state 的 participants 只查一次库。

### fill.py
