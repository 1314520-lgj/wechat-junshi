# 1.4.0 能力边界与未通过项

这次交付可运行的识别、证据、更正、模型协作、文件媒体理解、插件及更新功能，但不能宣称全部十项已完成真实验收。

1. 当前微信仅暴露窗口、面板级 UIAutomation，没有可靠账号 ID、消息 ID 或列表最新位置。自动填入开关默认关闭；即使开启，本版本也明确跳过自动填入，因为无法独立核对是否存在屏幕外的新消息。手动填入会检查当前会话、可见末尾消息、建议时效和空输入框，不发送。开放自动填入需要增加并真实验证该微信版本的可靠最新位置适配器，不能用模型判断替代。
2. 头像与昵称只是视觉线索。相同头像、同名、换头像均可能留下多条待确认人物，几百人的内部记录可存储，但没有完成几百人真实群聊识别率测试。当前按会话标题分区，同名会话仍有混淆风险，需人工核对；没有取得稳定会话账号 ID。只有已观察成员，不是全群名单。
3. 屏幕 OCR 支持文字、系统信息与媒体候选，视觉进一步分类。表情包、普通图片、视频、语音、引用、公告、投票、接龙的实际识别会受界面、字体与可见内容影响，不能保证“微信所有东西”。未知媒体不阻断可用文字回复。消息序号是应用观察次序；滚动历史不能证明微信服务器的完整消息顺序。
4. 语音和视频通过用户导入本地文件并明确关联消息后理解，当前不自动抓取微信原始媒体。最多处理前 180 秒、20MB；视频抽取三个时点，不等于完整理解视频。CPU Whisper 转写没有说话人分离；真实微信中文语音、群聊视频关联未完成验收。
5. 事实检查结合程序规则和模型复核，仍可能遗漏措辞变化、隐含承诺和 OCR 错误。四组真实模型测试不代表所有聊天都可靠，发送前仍需要用户核对。
6. 费用上限根据用户填写的单次估算控制，不是服务商账单硬上限。Harness 工具循环可能包含额外模型请求。视觉与 Harness 串行；尚无完全自由的多模型并发配置。模型目录最多 100 项，不支持字面意义的无限个模型。
7. 插件有权限声明、静态检查、运行验证、摘要绑定、故障隔离、停用与文件备份回滚，属于可信代码扩展。子进程不是 Windows 安全沙箱，不应启用未经审阅的恶意代码。新增代码必须再次验证；验证不保证绝对安全。
8. 本机证据数据库保存识别文字和更正记录，未整体加密；密钥、确认记忆和 Harness 选定上下文使用当前用户 DPAPI。原图裁剪缓存只在内存中，重启失效；官方 SDK 的用户目录可能保留会话日志。开发包不含真实聊天、密钥、用户备份。个人数据备份不要共享。
9. 深色界面、两次窗口尺寸、最小化恢复和普通私聊已测试；其他 DPI、浅色主题、不同微信版本、真实多人群同头像换头像、附件草稿、真实语音视频投票接龙引用仍需要授权样本完成真实验收。

解决路径：提供可只读验证的真实群聊和合法媒体文件；保留默认关闭自动填入；适配有可靠消息列表位置或原生消息 ID 的微信版本后重新测试；未来加入 Windows 权限隔离服务和服务商账单监控。不要把合成样本测试写成真实微信验收。
