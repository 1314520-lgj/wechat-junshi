# junshi（微信军师）技能

基于 JevChat-Windows（MIT，https://github.com/jev-chat/jev-chat-windows）的判断内核与
狗头军师（goutoujunshi，MIT，https://github.com/shengjidaguai-china/goutoujunshi）的关系原则，
在 DeepSeek Harness 里做微信回复副驾。

## 能力

1. **本地读屏**：后台自动识别微信窗口（无需选进程、启服务），截图 + 本地离线 OCR
   读出当前会话的最近消息，识别时微信窗口边缘有黄色提示框。
2. **判断**：按 Jev 7 题口径判断语境/意图/危险度（判断/排序用「判断模型」，默认 deepseek-chat，可换 v4-pro）：
   - literal_question：字面意思还是有潜台词
   - true_intent：确认在意 / 表达不满 / 要行动 / 要解释 / 闲聊 / 收尾
   - danger_level：紧张度 0–9
   - should_reply_now：下一条要不要给实质内容（事实没确认时选否，宁可少说）
   - best_action：核对记录 / 道歉 / 承诺 / 解释 / 回应理解 / 留白 / 商量安排
   - she_needs：道歉 / 行动 / 解释 / 在意 / 无需补充
   - tension_resolved：紧张是否已解除
3. **长期记忆档案**：每个联系人一份（`$DSH_HOME/.dsh-junshi-memory/`）：对方称呼偏好、近况、
   重要日期、性格观察、未完成约定、近期情绪基调；判断与起草都会参考，回复更贴人。
4. **起草**：模仿「我」的口吻（用词/句长/标点/语气词），反模板、去 AI 味，
   3 条不是「温暖版/负责版/行动版」而是同一人三个心情下随手打的；带着判断小抄写。
5. **排序**：给定完整对话（不只是候选）给出每条候选的胜出概率并推荐第一条。
6. **安全填入**：只把文字填进微信输入框，**绝不自动发送、绝不按回车**；
   不碰转账/红包/借钱；发不发由用户自己决定。

## 工具

- `junshi_status`：读当前微信会话状态（会话名、最近消息、判断摘要、候选）。
- `junshi_reply`：对当前会话重新生成候选（判断→起草→排序，最长约 90 秒）。
- `junshi_fill`：把第 N 条候选安全填入微信输入框。
- `junshi_analyze_text`：对用户贴出的对话文本跑完整链路（无需打开微信）。

## 使用要点

- 用户问「这条怎么回」「帮我看看 TA 什么意思」且微信里有会话时：
  先 `junshi_status` 看现状，再 `junshi_reply` 生成，最后按用户确认 `junshi_fill` 填入。
- 只回一条时：先给一条可直接复制发送的成品，再给发送时机、主要代价与后续分支。
- 情绪先落地（先接住情绪），再分清事实，最后给能执行的选择；不读心、不编造；
  区分「截图能证明」「转述提示」「仍未知」。
- 危险度 ≥ 6、对方明确拒绝或要求停止时：不强行推进、不教操控/贬低/哄骗话术，
  提醒用户保留最终决定权。
- 隐私硬约束：OCR 离线、截图只进内存、密钥只在官方凭据里、绝不自动发送。
